# The procedural block font

Nothing in this program ships a picture of a character.

## 1. A glyph is a function, not a drawing

A glyph is an 8×8 bitmap — `[u8; 8]`, one byte per row, **bit 7 leftmost**,
which is the order the TED reads a character definition, so the baked table
needs no bit reversal.

Every one of them is produced by a generator in `font.rs`:

| Generator | Produces |
|---|---|
| `dither(level)` | an ordered dither at `level` of 64 |
| `quadrant(mask)` | a 2×2 block from a 4-bit mask |
| `subcell24(mask)` | a 2×4 block from an 8-bit mask |
| `half_plane(a, b, c)` | pixels where `ax + by < c` — every straight edge |
| `facade(bays, floors, lit)` | a window grid with mullions and spandrels |
| `hrule` / `vrule` | bands and piers |
| `rain_streak(dx, phase)` | a leaning streak with gaps |
| `disc_quadrant(r, qx, qy)` | one quarter of the moon |
| `speck(n)` | a single pixel, for stars |

and combined by `over`, `less`, `shift` and `xform` — which flips, mirrors,
transposes and inverts, so a right-facing slope is the left-facing one
transposed rather than a second hand-drawn shape.

Three things follow, and they are the reason it is built this way:

1. **The Plus/4 gets a real font.** The TED can be pointed at a character set
   in RAM, so the 128 glyphs are baked into 1 KB and copied there at boot.
   The machine then draws shapes no PETSCII set contains, at no per-frame
   cost, because they are still just screen codes.
2. **The terminal gets the same shapes.** Or as near as a terminal can.
3. **Transformations are free**, so the catalogue stores one shape per
   family and derives the rest.

## 2. Dithering, and why it is ordered

`BAYER8` is the classic 8×8 ordered-dither threshold matrix, and
`dither(n)` sets exactly `n` of the 64 pixels — which is tested, because a
ramp that is not linear in coverage is a ramp with a visible step in it.

Ordered dither rather than error diffusion, because **a character cell is not
a pixel**. It is re-chosen from scratch every frame, and a diffused error has
nowhere to go between frames except into a crawling shimmer. An ordered
matrix is stable: the same intensity always yields the same glyph, so a wall
that is not moving does not sparkle.

The same argument, one level up, is why the facade sampler quantises the
floor and bay indices by the level of detail. A screen cell forty units away
spans four floors; asking "is *this* window lit" four times and getting four
different answers produces noise at exactly the frequency the eye is worst
at. One cell asks the question once.

## 3. The catalogue

128 shapes, and 128 is not arbitrary. When the TED takes character
definitions from RAM rather than from ROM it reads a **1 KB** set — 128
definitions of eight bytes — and bit 7 of a screen code becomes a
reverse-video flag rather than an address bit. So 128 is the whole budget,
codes 128–255 come out free as inverses of the first half, and the ROM
alphabet is gone the moment the custom set is installed.

| Range | Family | Count |
|---:|---|---:|
| 0 | blank | 1 |
| 1–7 | dither, lightest to heaviest | 7 |
| 8 | solid | 1 |
| 9–23 | 2×2 quadrant masks 1–15 | 15 |
| 24–31 | eighth-fills from the bottom up | 8 |
| 32–39 | edge slopes | 8 |
| 40–55 | facade tiles: 4 configurations × 4 lit patterns | 16 |
| 56–59 | mullions | 4 |
| 60–63 | spandrel, cornice, ledge, parapet | 4 |
| 64–69 | fire escape: zigzags, landing, rail, ladder, bracket | 6 |
| 70–73 | roofscape: parapet, water tank, plant, mast | 4 |
| 74–81 | road surfaces and markings | 8 |
| 82–87 | flora | 6 |
| 88–93 | street furniture | 6 |
| 94–97 | vehicles | 4 |
| 98–99 | pedestrians | 2 |
| 100–107 | rain phases | 8 |
| 108–111 | the moon, as four quadrants | 4 |
| 112–115 | its halo | 4 |
| 116–123 | star positions within a cell | 8 |
| 124–127 | haze | 4 |

`make sheet` prints all of them with their bitmaps. The output is in
[`media/glyph-sheet.txt`](media/glyph-sheet.txt); a font that is generated by
a function still has to be *looked at* by a person.

## 4. The three renderings

The renderer never emits a character. It emits a catalogue index, and the
output device decides.

### Plus/4 — the identity

Screen code = catalogue index. The colour byte is already `luminance << 4 |
hue`, which is what the TED wants in colour RAM. So on the machine, the
renderer's output *is* the hardware bytes and there is no conversion step at
all.

### Terminal, ASCII — the mode the project is named for

`glyph::ASCII` maps all 128 indices to the 95 printable characters of 7-bit
ASCII. Every one of them is on the keyboard in front of you, and the mode
survives `ssh` to anything. A test asserts the whole table stays inside
`' '..='~'`, because the failure mode otherwise is a stray byte that renders
as a box on somebody else's terminal.

The families read as ramps — the dithers climb `. : - = + * #`, the fills
climb `_ . - = + # @` — and a test checks the ramp never reverses, because a
ramp that goes backwards is visible as a seam.

The four *facade configurations* are four visually distinct window textures
rather than four densities of one, which is what makes a skyline read as a
row of distinct buildings:

```
config 0   8 0 o .        config 2   X x + :
config 1   H # = -        config 3   M W m n
```

Which one a building uses comes from the **lot's seed and nothing else**, so
it is a property of the building rather than of the window. One tower is
drawn in `X`, its neighbour in `0`, a third in `8`.

### Terminal, Unicode — block elements

`glyph::UNICODE` uses the block-element and box-drawing ranges, whose
quadrants and eighths are the same vocabulary the Commodore character ROM
had — which is why the catalogue is built out of quadrants and eighths in
the first place. The quadrant masks were *numbered* to match Unicode's
ordering, so those fifteen are exact rather than approximate, and so are the
eight eighth-fills.

### Why the tables are hand-authored

A terminal's font is unknown at build time and `X` is not `X`-shaped in
every one of them, so an automatic match would be fitting to a guess. What
*is* checked is that each table is complete, that ASCII stays inside seven
bits, and that the ramps stay monotonic.

The bitmaps do carry a coverage-and-moments signature (`font::moments`) for
the day there is a font file to match against. See the backlog.

## 5. Sprites are ASCII art in the source

Billboards — lamp posts, hydrants, cars, coins — are written as eight rows
of eight characters, in `sprite.rs`, and each character names a catalogue
glyph. That is not laziness. The whole project is about what a shape looks
like when it is made of characters, and a sprite editor that is not itself
made of characters would be lying about the medium. It also means adding a
mailbox is four lines of art rather than a data file and a loader.

```rust
const MAILBOX_ART: [&str; 8] = [
    "        ",
    "        ",
    "  ####  ",
    " ###### ",
    " ###### ",
    "   ||   ",
    "   ||   ",
    "  ====  ",
];
```
